# Expected-red R1 recovery tests (run under TZ=Asia/Karachi).
# Each line is an exact test name. When a substage fixes a defect, move the
# test to the green suite and delete its line here in the same change.
F-1 UI layer (hang): committed sale must show a receipt, not an endless spinner
F-1 UI layer (throw): committed sale must not be reported as "Nothing was charged"
F-1 data layer: post-commit sync failure escapes, cart is not cleared, retry creates a second sale
F-2: voided credit sale converges to opening stock and zero Udhaar on the voiding device
F-3 cross-device credit limit: second offline Udhaar sale is recorded or flagged, never retried forever
F-3 zero-amount payment: locally committed sale reaches a terminal state instead of retrying forever
O-2 scenario A: late offline upload from device A reaches device B
O-2 scenario B: a future-clock upload does not hide later normal rows from device B
O-6: SyncWorker.runOnce must not throw when its lease was lost after a successful upload
R1.3 v2 void: server uses the client compensation ids
R1.4 server_seq: pulled rows expose a server-assigned order
R1.5 DPA01: a sale from a revoked device is rejected with DPA01
R1.5 DPC01: same sale id with different content is rejected with DPC01
R1.5 DPV01: a zero-amount payment row is rejected with stable code DPV01
R1.5 accepted_flagged: offline credit sale over the limit is recorded and flagged
T-1 (local): uploaded sale timestamp is the real instant on this device
T-1: synced sale keeps its real instant on the server
T-1b: rows sharing one second do not loop or re-fetch through a truncated cursor
